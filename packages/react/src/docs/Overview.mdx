# Agent UI

Agent application components for the Cloudflare Agents SDK, built with Kumo.

React components for building agentic interfaces: transcripts, tool calls, reasoning, prompt
composers, and more. Components are controlled — they receive state and callbacks through props
and never connect to an agent, open a WebSocket, or call an SDK directly. Cloudflare-specific
state translation lives in a dedicated adapter export (`@agent-ui/react/agents`).

## Component catalog

Everything ships from `@agent-ui/react`, split across two entry points so SDK-free components stay
decoupled from any agent runtime.

### Adapter — `@agent-ui/react/agents`

The `agents` entry point bridges Cloudflare Agents / AI SDK chat state into the core components:

- `AgentChat` compound — `Root`, `Messages`, and `Preset`. The full compound, including the
  zero-config `Preset`, exists only here.
- `AgentChatPreset` — the standalone `Preset` component over a raw chat object
  (<a target="_top" href="/?path=/docs/agent-ui-agentchatpreset--docs">docs</a>).
- `useAgentChatUI` — headless adapter that maps raw chat state into the SDK-free
  `AgentChatViewModel`.
- `useAgentComposer` — composer state and submit plumbing for building custom inputs.
- `mapChatStatus`, `mapToolState`, `toAgentMessageParts`, `getMessageText` — state and part mappers.

## Design principles

- **Controlled by default.** Every component receives state and callbacks through props. There is
  no hidden networking; you own the data flow and the agent connection.
- **Structured parts, not blobs.** Messages are composed from typed parts — text, tool, reasoning,
  file, and custom — so renderers can branch per content type.
- **Built on Kumo.** Visual treatments use Kumo semantic tokens (surfaces, status, text) and adapt
  to the active color mode without `dark:` variants. Library class names are prefixed `agent-ui-`.
- **Accessible and keyboard-safe.** Semantic HTML, visible focus, accessible names, and reduced-motion
  behavior are preserved throughout.
